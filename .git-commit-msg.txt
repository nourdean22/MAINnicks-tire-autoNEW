wave-181.12: CRITICAL prerender circular-bug fix + 18 city metaTitles synced cities.ts → prerendered HTML

=== THE BUG (silent for entire prerender history of this codebase) ===

server/prerender-middleware.ts intercepts bot User-Agents and serves
the prerendered HTML directly from disk. The prerender SCRIPT
(scripts/prerender.mjs + prerender-comparison-only.mjs +
regen-prerender.mjs) sets puppeteer's User-Agent to Googlebot so the
server treats it as a bot.

PROBLEM: when puppeteer requests /tire-repair-cleveland during the
prerender, the middleware sees Googlebot UA → serves
prerendered/tire-repair-cleveland/index.html (the OLD file) → puppeteer
captures it → "regenerated" file is identical to input.

EVERY prerender pass was just REPLAYING the prior output. No actual
React render was being captured. Title/meta changes via SEOHead were
silently ignored. The ONLY changes that propagated were direct
regex injections in scripts/prerender.mjs:339 against routes.ts titles
(which worked because the script post-processes the captured HTML).

For pages where the title is set via React (e.g. CityPage reading
cities.ts.metaTitle and calling SEOHead with it), the SEOHead update
NEVER reached the prerendered HTML — puppeteer was capturing the
already-prerendered HTML from disk, where the title was whatever it
was when the file was originally written.

Discovered when /parma-heights-auto-repair stayed at "Free Uber Both
Ways" title even after cities.ts was updated to "Used Tires $60 ·
Open Sundays" + a fresh prerender ran. Same content captured back.

=== THE FIX ===

server/prerender-middleware.ts:
- Added bypass: when PRERENDER_MODE=true env var is set, the
  middleware falls through (does NOT serve prerendered HTML). The
  prerender server spawn sets this env (wave-181.3), so during
  prerender runs the middleware is bypassed and puppeteer hits the
  live React render.

Result verified: /parma-heights-auto-repair title NOW shows
"Parma Heights Auto Repair · Used Tires $60 · Open Sundays | Nick's"
in the regenerated HTML. Previously stuck at "Free Uber Both Ways".

=== Implications for prior waves ===

Many of the wave-181.5+/.6/.7/.8/.9/.10 changes were potentially
silent no-ops at the prerendered-HTML level because of this bug. The
ROUTES.TS title changes worked (script regex injection). The CITIES.TS
+ SEOHead changes did NOT propagate.

Wave-181.12's fresh prerender pass after the middleware bypass
captures the correct rendered output for all 42 affected routes.
After Railway redeploys, the live site serves the corrected HTML.
