## In order: where each step fires

Each line starts with the step's number and name in `SKILL.md`; `managerSkill.test.mjs` fails if a number, a name or the order drifts.

- 1 Recover state: `ledger-check.mjs` fails on the stale `pending` row (f) before dispatch, and `gh pr view` flags a MERGED PR under an open row.
- 2 Spec: two alternatives (hook code, native ask rules), the 10x option, kill criteria, and the doc quote that upgrades a CLAIM (c, l).
- 5 Dispatch: brief v2 with PATH EXCEPTIONS naming `CONTROL-CANARY-COVERAGE.md` up front, DESIGN, FIXTURES, PITFALLS, SELF-AUDIT; one decision per message (g, h).
- 6 Check every return: unlabelled receipts are sent back (j).
- 7 Probe it yourself: boundary probe at 200, 201 and last position (a).
- 8 Check the names: the 135 leaves resolved entry by entry by someone other than the author (b).
- 10 Review before the PR opens: lenses and skeptics run before the first push, not after the bot reviewer (d).
- 12 Consumer check: a fresh session once the primary has the change (i).
- 13 Merge: `merge-gate.mjs` (e).
- 15 Log and learn: one `MERGED` / `this PR` row plus a metrics row (f, k).

## Added from a peer manager's report (CLAIM: relayed by another session, not re-measured here)

After the replay, the status manager session reported six measured lessons from three lane jobs the same day. All six are now in the skill:
list out-of-lane files in the brief up front (a lane's pre-commit hook runs app-wide checks); compare `check-lane-paths` flags with the brief's
PATH EXCEPTIONS; send review fixes to the finished lane with SendMessage; independent adversarial review found real high-severity defects in 2
of 3 lane outputs that the lanes' own green tests missed (step 10); cherry-pick lane commits onto current origin/main; count reviewers and
background suites toward the heavy-run limit.

## What this does not claim

- (d) is untested on history. Whether the six lenses would have found #3040's five findings is UNKNOWN; replaying them needs the
  workflow opt-in: `Workflow({ name: "adversarial-review", args: { worktree: "<a checkout that has 2f28cb772>", base: "2f28cb772^", head: "2f28cb772", change: "#3040: guard coverage for MCP and native runners" } })`.
- (a) catches caps the manager can find by grep. A limit that lives in a dependency or a runtime (a shell's persistent cwd, which
  the operator accepted as documented) is found only by a probe someone thinks to write.
- (h) and the "register" half of (j) rest on the job brief, not on a transcript.
- None of this changes what a guard can enforce. The PreToolUse hook is Claude-only; Codex, Cursor and humans get no hook.
