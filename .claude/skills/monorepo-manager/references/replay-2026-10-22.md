## In order: where each step fires

Each line starts with the step's number and name in `SKILL.md`; `managerSkill.test.mjs` fails if a number, a name or the order drifts.

- 1 Recover state: the turn contract runs first: the FIX FIRST line is fixed or declined in words (d); Skill calls come before the `Skills:` line (c).
- 3 Pre-clear: the protected actions of an overnight job are listed and cleared before Nour leaves (e).
- 6 Dispatch: a brief that reads shop records carries the SHOP DATA block, or the call is refused (b).
- 8 Relay: a session's claim is checked against the shop's meanings, memory and the source before Nour hears it (a).
- 16 Report: CI and live states come from reads made in the same turn (f).

## What this does not claim

- (a) is not mechanical. The hooks catch the CI and live forms of an unchecked relay (f), not a wrong shop fact: no check
  can know that "0 declines" is false without the shop's own definition. The relay step and USER.md carry that.
- (c) and (f) send a turn back ONCE per prompt; a second wrong line in the same turn goes through. A seatbelt, not a driver.
- (b) covers Agent, Task and `start_session` briefs, not a SendMessage follow-up to a running session.
- (d) counts any tool call that NAMES a fix (its script or task name) as acting on it, a read of the script included; it
  checks that the session turned to the fix, not that the fix worked. The next SessionStart `[health]` line is that proof.
- The hooks load from the PRIMARY checkout's `.claude/settings.json`: none of this is live in a session until the primary
  has the merge and a NEW session starts (step 14).
