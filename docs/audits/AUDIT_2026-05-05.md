## §4 — Security Headers + Auth + CSP

### Production response headers (verified live)

| Header | Value | Verdict |
|---|---|---|
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | ✅ |
| `X-Frame-Options` | `DENY` | ✅ |
| `X-Content-Type-Options` | `nosniff` | ✅ |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | ✅ |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | ✅ |
| `Content-Security-Policy` | full directive set | ✅ |
| `X-Xss-Protection` | `0` | ✅ (modern; CSP is the real defense) |

CSP allows `'unsafe-inline'` for scripts and styles — the standard React pragma. Reasonable.

### Auth model

- **Google OAuth** for the owner sign-in. Token from Google → server upserts `users` row.
- **Admin role auto-grant** via `server/db.ts`:
  - If `user.openId === OWNER_OPEN_ID` → `role = 'admin'`
  - Fallback: if `OWNER_OPEN_ID` not set AND `user.email === CEO_EMAIL` → bootstrap admin
- **Push notification admin flag** (`/api/push-subscribe`) requires an admin API key in headers, not just session — defense-in-depth.

### Risks

- **Single-owner gate by design.** Adding a second admin (e.g., a manager) means manually flipping the `role` column in DB or extending the auto-grant logic. No RBAC; no per-permission scope. If you grow staff, this becomes load-bearing tech debt.
- **No CSRF token** observed on POST routes — the OAuth session cookie is the only barrier. tRPC over fetch with credentialed cookies is generally safe in modern browsers, but documenting the threat model would help.

## §8 — Admin Auth + Access Control

### Current model

```
Google OAuth login → upsert users row
  ↓
if user.openId === OWNER_OPEN_ID  → role = 'admin'
elif !OWNER_OPEN_ID && user.email === CEO_EMAIL  → role = 'admin' (bootstrap)
else                                              → role = 'customer'
```

- `/admin` and `/admin/*` routes check `role === 'admin'` server-side via tRPC middleware.
- `Disallow: /admin` in robots.txt blocks crawlers.
- Push notification admin flag adds API-key defense-in-depth.

### Gaps

- **No granular permissions.** Admin = full access. There's no "viewer," "support," "marketing" role. If you ever hire someone to manage just CampaignsSection, they'd need full admin.
- **No audit log of admin actions.** If a subordinate ever has access, you can't trace who edited what.
- **No 2FA on the OAuth login.** Google itself enforces 2FA if you do, but the app doesn't enforce.
- **Session expiry not measured** in this audit. If sessions are long-lived, theft of an open laptop = full admin access.

### If you grow to 2+ admins, in priority order

1. Add `role: 'admin' | 'manager' | 'viewer'` enum, gate routes by enum.
2. Add audit_log table — every admin mutation writes a row.
3. Force 2FA at the Google OAuth scope.
4. Add session expiry + rotating refresh.
