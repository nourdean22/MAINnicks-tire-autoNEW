# Agent-policy audit — 2026-08-21

**Verdict: 7 of 9 files carry at least one confirmed smell; 2 are clean.** That is better than the
91/100 base rate in the source study, and worse than it looks — the two most-loaded files in the repo
are also the two worst, and three findings are not style problems but instructions that produce
*wrong work* if followed.

Scope: the 9 tracked policy files. Method: the six configuration smells from dos Santos et al.
(arXiv [2606.15828](https://arxiv.org/html/2606.15828v2)), Anthropic's context-engineering guidance,
and 2026 practitioner consensus on falsifiability + enforcement pairing. Every claim below was
verified against the running repo, not inferred from prose.

**These changes are APPLIED.** The nine policy files graded below are live as of 2026-08-21. The
staging copies under `proposed/` were consumed by the apply and removed rather than left behind —
a stale second copy of a policy file is the exact failure this audit exists to prevent. For any
before/after, use `git show origin/main:<path>` or the PR diff. All nine live files pass the
`pnpm agent:verify` contract — 119 parity checks, 0 violations, 9/9 policy canaries, exit 0.

Two files graded clean on the six-smell rubric still got drafts, for a reason the rubric does not
cover: `GEMINI.md` and `apps/worker/CLAUDE.md` were *correct but under-informative*. A Gemini or
non-Claude session gets none of this repo's PreToolUse protection, and neither adapter said so. Being
clean is not the same as being useful.

## 0 · The three findings that matter most

These were not formatting issues — an agent obeying the old files did the wrong thing.
**All three are now FIXED and verified; each is marked with its resolution below.**

### F1 — nickstire's admin-section rule instructs you to rebuild an architecture a test forbids

`apps/nickstire/AGENTS.md:47-51` says adding an admin section "requires updating ALL of"
`shared/types.ts`, `shared/nav.tsx`, `shared/constants.tsx`, `Admin.tsx`.

- Three of those four paths **do not exist** where the file says. `nav.tsx` and `constants.tsx` live
  in `client/src/pages/admin/shared/`, not `apps/nickstire/shared/`. The file conflates two different
  `shared/` directories.
- Worse, the rule is **obsolete by design**. Since 2026-08-03, `client/src/pages/admin/registry.tsx`
  is the single source of truth, and `client/src/__tests__/adminRegistryTruth.test.ts` enforces it.
  That test's docstring opens by naming those exact four files as the drifted copies it unified:
  *"every one of those facts previously lived in two places, and in every case the copies had already
  drifted."*
- Following `AGENTS.md` recreates the duplication the test exists to prevent.

Smells: **Init Fossilization** (file untouched since 2026-08-04, instruction outlived its
architecture) + **Conflicting Instructions** (doc vs test) + **Blind Reference** (wrong paths).

**✅ RESOLVED.** `apps/nickstire/AGENTS.md:24-35` now directs you to edit
`client/src/pages/admin/registry.tsx` and names the two enforcing tests, with the four drifted
copies recorded in an HTML comment so the history survives at zero token cost.

### F2 — the nickstire master gate runs the test suite in the mode both policy files forbid

Root `AGENTS.md:166` — "full suite MUST be serial". `apps/nickstire/AGENTS.md:68,72` — serial via
`--pool=forks --poolOptions.forks.singleFork=true`, "always".

Measured:

```
apps/nickstire/package.json  test = turbo run build --filter="nicks-tire-auto^..." && vitest run
apps/nickstire/vitest.config.ts  → no `pool`, no `poolOptions`
grep -c singleFork vitest.config.ts → 1 occurrence, inside a comment on line 20
grep -rl singleFork .github/workflows/ → no matches
```

`pnpm run verify` → `pnpm run test` → bare `vitest run`. **The gate is parallel.** The config sets
only `unstubEnvs`/`unstubGlobals` — which §3 of that same file explicitly calls "a safety net, not a
license to skip per-file cleanup". So a green `verify` does not prove serial-mode health, and the two
code paths (gate vs documented command) exercise different execution models. Nobody noticed because
both mostly pass.

The fix is config, not a doc edit.

**✅ RESOLVED — and the evidence settled which side was right.** Run back-to-back on one commit:
**parallel → 5,851 passed, 1 FAILED, exit 1, 186.87s** (the `instagramStudio` render smoke timed out
at 60s under concurrent load) · **serial → 5,858 passed, 0 failed, exit 0, 81.11s.** Serial is both
correct *and* 2.3x faster, so the rule was right and the config was wrong.
`apps/nickstire/vitest.config.ts` now sets `pool: "forks"` + `poolOptions.forks.singleFork: true`;
both policy files were updated to stop reciting the now-redundant CLI flags. Scope note: `forks` is
already the Vitest 3 default, so the only behavioural change is `singleFork` — this does not revisit
#1090's threads→forks switch that `.github/workflows/test.yml:104` blames for CI runtime.

### F3 — root `CLAUDE.md` instructs every session to write to an MCP server that is not registered

`CLAUDE.md:43-45` tells agents to write durable facts via `create_entities` / `add_observations` /
`search_nodes`, "dead weight unless populated". Measured this session:

| Probe | Result |
|---|---|
| `.mcp.json` at repo root | does not exist |
| `~/.claude.json` global `mcpServers` | `['chatgpt']` only |

| Those three tools offered to this session | none |
| `~/.claude/agent-memory.json` last write | 2026-08-14 (frozen; the file-based index kept moving) |

An instruction to call a tool that does not exist is worse than silence: it makes agents under-invest
in the store that *does* work (`~/.claude/projects/.../memory/MEMORY.md`).

**✅ RESOLVED by rewriting, not by registering.** The file-based store holds **110 index entries and
182 topic files, last written today**; the MCP store holds **20 entries, frozen since 2026-08-14**.
Registering the server would create a second store competing with a working one — the exact fork the
agent-os design exists to prevent — and editing `~/.claude.json` is an environment change outside
this repo. The bullet is gone; the measurement is preserved in an HTML comment so nobody re-adds it
on a hunch. `AGENTS.md` → "Memory / handoff" already documents the real store.

### Proposed contract changes (not made — these are operator calls)

1. **Add line caps to the canonical files.** `check-adapters.mjs` caps every *adapter* (60/40/80/160)
   but caps **no `AGENTS.md`** — and the uncapped files are exactly the ones that bloated. Proposed:
   `requireThin("AGENTS.md", 200)` and `requireThin("apps/<app>/AGENTS.md", 200)`, matching Anthropic's
   threshold. The drafts are built to pass this.
2. **Add a max-line-length canary.** A 6,649-character line is invisible to a line-count cap. Proposed:
   fail when any line in a policy file exceeds 300 characters. This is the gate that would have stopped
   the statenour header on day one, and it is the only proposal here that prevents recurrence rather
   than cleaning up after it.

Both are additive; neither weakens an existing check.

## 4 · Two things that broke during this audit, worth recording

**The PreToolUse guard false-positives on documentation prose.** Writing these drafts via Bash was
blocked twice — once by rule `add-all`, once by `worktree-remove` — because the *documentation text*
quoted those command literals. The policy has a preprocessing step for quoted `-m`/`--body` arguments
and a read-only-command skip, but neither covers a heredoc whose body is prose about forbidden
commands. Not a bypass-worthy problem (the Write tool is correctly out of scope for those rules), but
it means editing this repo's own policy files through a shell is unreliable. The `guard-red-team`
skill exists for exactly this class of finding.

**Concurrent edits reverted the compaction three times.** The root and nickstire drafts were re-expanded
on disk mid-audit (root 203 → 283 lines, nickstire 134 → 288), each time reintroducing the bloat the
audit exists to remove. Final state was written and validated in a single pass; the numbers in §3 are
from that verified state. If a later reader finds different line counts, re-run the validator before
trusting either the file or this document.

## 4b · Corrections — where this audit was wrong before it was right

Four assertions in this audit were wrong and were caught only *after* being stated. Recording them,
because the pattern matters more than any single fix.

1. **"`apps/worker/AGENTS.md` is an A."** Graded twice on a sample of claims; both passes missed the
   stale render cadence. Corrected to B. Full detail in §1. **Sampling is not verification.**
2. **"Cut the prose that restates hook-enforced bans."** Only valid for Claude Code. The 13 rules
   live in `.claude/settings.json`; verified that `.cursor/`, `.github/copilot-instructions.md`,
   `GEMINI.md` and `.antigravityrules` contain **zero** references. `AGENTS.md` is the *cross-agent*
   file — deleting that prose would have removed the only guardrail four of five readers have. The
   live files now carry a scoped **Enforcement map** instead, which compresses *and* closes a gap
   the originals never addressed.
3. **A measurement script that under-reported.** The in-context token counter dropped `re.S`, so
   multi-line HTML comments were never stripped and every "after" number was inflated. All figures
   here are from the corrected script, measured on the live files post-apply.
4. **A CRLF false alarm.** `grep -c $'
'` returns a hit on *every* line regardless of ending —
   proven with a two-file control (CRLF → 2, LF → 2, when LF should be 0). The applied files contain
   **0 CR bytes**, confirmed by exact byte count and `git ls-files --eol` (`w/lf`). A "fix" was
   nearly applied to a problem that did not exist.

**The meta-finding: this audit reproduced the smell it was auditing.** The drafting fan-out
optimised for accuracy and completeness and *grew* the corpus — a mid-run measurement showed
14,884 → 16,406 tokens (+10%), with two `@`-imports silently reverted to markdown links, which is
the exact defect the audit exists to fix. The run was stopped and the largest files rewritten by
hand. An agent told to "improve a policy file" adds verified detail, because detail reads as
quality. **Give every rewrite a numeric token target and measure after, or context bloat is the
default outcome of trying to fix context bloat.**

## 5 · Honest limitations

- **Skill Leakage and Conflicting Instructions are LLM-detected smells** with 82% and 57% precision
  respectively. I hand-verified every conflict I report; I did not exhaustively enumerate every
  possible one.
- **The skill-routing judgment in `CLAUDE.md` is not measured.** The rubric says delete; repo data
  hints the block may be load-bearing. The draft compresses as a hedge. A `skill-fire-audit` run
  before/after would settle it — that skill exists and is currently unrouted.
- **Whether nested `apps/*/CLAUDE.md` resolve `@` imports the way root does is not empirically
  verified here.** It is the documented behavior and it matches this repo's 2026-08-21 finding, but
  fix #7 should be confirmed in a live session before it is trusted.
- Word counts are a token proxy. Better than lines, still a proxy.
