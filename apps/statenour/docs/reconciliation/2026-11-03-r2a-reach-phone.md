> ## 2026-11-03 · The phone hears about goal check-ins due and the weekly review (job 2026-11-02-nour-os-interconnect, R2a) · 1 ship

> Nour, 2026-11-03 10:08 EST: "i think we have alot of these and also audit them if not upgrade them too". The R1 audit found two signals that existed and never reached the phone: goals due a check-in (`pickCheckInDue`, lib/brain/goal-pace.ts, read only by Home) and the weekly review (the `weekly_review_nudge` category had no writer).
>
> - **Check-in count on the morning push.** `pushBodyFromBrief(text, checkInsDue)` (lib/inngest/functions/morning-brief.ts) ends the body with "N goals need a check-in" (singular "1 goal needs") after the private-section cut, with room kept so the 200-char cap never cuts the line. It is a count only: the push read selects no title, and the Goals section stays cut (PR #3221). `countCheckInsDue` makes Home's read (active goals, newest check_in event per goal) and counts with the same `checkInOverdueDays >= 0` test `pickCheckInDue` uses. A failed read logs `check_in_count_failed` and adds no line; the brief still ships. The Telegram fallback carries the same line.
> - **"Weekly review ready", once per ISO week.** After the review row is written (the upsert now reports whether it landed), app/api/cron/weekly-review/route.ts claims `weekly_review_nudge` / `YYYY-WNN` with a create: P2002 means another run took the week and nothing is sent; any other create error sends nothing (no claim, no push). The week is the review's ET Monday, never the UTC run date (the cron fires Monday 03:00 UTC, already the next ISO week in UTC). The push is level medium, tag `weekly-review-ready-<week>`, body names the week only (no review text). The claim is kept when a device took the push or quiet hours held it for the Pulse sheet; when the push threw or reached nothing, the claim is deleted by its own id so a rerun can try again.
> - **The marker survives the sweeps.** Written directly (marked `brain-memory-direct-write:`), not through remember(), with no `expiresAt` and confidence 1.0: pruneNoise's expiry arm needs `expiresAt < now` and its stale arm `confidence < 0.1`, and data-cleanup's hard delete (app/api/cron/data-cleanup/route.ts:93) needs one of the same two, with no retention row for the category in config/retention.ts. The category joins `CONSOLIDATION_EXCLUDE_CATEGORIES`, like `proactive_push_sent`, so the nightly merge cannot rewrite or soft-delete a week's marker. The category's doc comment now names its real writer.
