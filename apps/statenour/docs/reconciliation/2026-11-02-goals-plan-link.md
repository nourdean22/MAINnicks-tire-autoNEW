> ## 2026-11-02 · Goal "Plan it" links the mission, finishes the plan, and keeps the done criteria (job 2026-11-02-nour-os-interconnect, PR A) · 1 ship
>
> Nour (16:50 EST): the circled milestones panel "is failing to turn those into tasks on the missions page and not able to track them to the goal". Prod read 21:45Z (read-only): 13 live missions, 0 with `lifeGoalId`, 0 with `planData`; the mission the flow made that afternoon had 3 tasks (from the goal's own next-step prompt), no plan, no goal link. `agent_traces`: 3 of 3 `plan-project:plan` calls that day ended `provider_emergency` at 53-58 s; the 7 `plan-project:milestones` calls (same model, ollama/minimax-m3) succeeded.
>
> - **Root causes.** (1) `missionCreateSchema` had no `lifeGoalId`, so zod stripped the link on every create. (2) The plan prompt asked a local model for 15-30 steps with costs, tools, risks and a weekend schedule (~8,000 output tokens) under the 100 s provider timeout (`lib/ai/provider.ts:1296`), so no provider ever finished; the persist failure path was a `log.warn`, and `spawnTasks` then had no plan (400, swallowed as best-effort). (3) The mission edit drawer sent `description`, which no schema accepts: "what does done look like" was dropped on every save (the column is `completionCriteria`).
> - **Fix.** Create and update schemas accept `lifeGoalId` and `completionCriteria`; the flow sends the goal id, the last milestone as the finish line, and the goal's deadline. With confirmed milestones the planner uses a compact prompt (2-4 steps per milestone, no cost/tool/schedule sections) with a 170 s timeout (the tRPC route allows 180); when every provider still fails, the milestones become the plan (one checkpoint step each, `fallback: "skeleton"`), so spawn always has something to spawn. A failed planData write now fails the call. `getGoals` lists each goal's missions (phase count, tasks done/total) and the goal card links to them; `listMissions` includes the goal and the mission card and drawer show it; the drawer's field is now "done when" and saves `completionCriteria`.
> - **Not changed.** The 3 tasks and the mission from the afternoon stay as they are (a production write to relink them waits for Nour's go); the full-plan prompt without milestones (ProjectDetail "plan" / "replan") is untouched and still risks the 100 s timeout on a slow local model.
>
> **Flagged · NOT fixed**
> - `plan-project:plan` without milestones keeps the 15-30 step prompt and the 100 s default: the same timeout can hit the missions page's own planner. Measure its traces before changing it.
> - The milestones ladder lives only in `Mission.planData.phases`; the goal has no milestone rows of its own, so progress on the goal card is still task-count based.
