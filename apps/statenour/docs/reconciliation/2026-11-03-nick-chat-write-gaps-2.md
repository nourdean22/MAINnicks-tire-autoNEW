> - **Per-day habit grid.** `lib/services/daily-backfill.ts` `habitDays(tasks, days, endDay)`: the last N ET days, newest first, per habit, from ONE `task_events` read (completed + uncompleted, created on or after the window's first ET midnight). A day is done when its events net a completion (a backfill counts on its own day, an uncheck takes it back); with no net word from the events the row's own run vouches (a check whose fire-and-forget event write failed, or pre-log history); for a WEEKLY row the count is a tally, so only its `lastCompletedAt` day vouches. A failed read throws. Readers: `getHabitStreaks` (now `{ completed, total: 7, streak, last7 }` per habit; a failed habit read is `{ error: "habits unknown" }` and a failed ledger read is `last7: "unknown"`, never a week of not-done), `GET /api/habits` (`days` per habit; `completed` is the requested ET day; it also stops reading soft-deleted habits, stops reading the day off `lastCompletedAt`'s UTC date, and answers an error instead of every habit "not done" on a failed read), `lib/brain/legacy-shims.ts` `recentDailyHabits` (correlation-finder, predictive-engine, page-data, `/api/habits/streaks`), and the /missions rhythm window in `lib/missions/deck.ts`, which counted `completed` events only, so an uncheck would have kept the row "done".

> - **Relationship ledger from chat.** Prior art: Nick's `person.logInteraction` action block writes the same ledger, but it runs after the reply (`deferred-background-work.ts`), so a name it could not resolve never came back in the turn, and it accepts a typo-close fuzzy match. Telegram keeps typo matches (its reply names the person) and now says "matches more than one person" instead of logging to whichever row Postgres returned first. The action block skips when a `chat_tool` row for the same person exists from the last 10 minutes, so one contact is one row; the behaviour directive tells Nick to prefer the tool. Reachability: an `EXPLICIT_WRITE_INTENTS` pin on the ledger grammar (a signed amount, then for/to/with and a name, never an article).
