## Critical findings (production-impact)

### 🔴 Wave-73: hook-after-early-return crashed admin Overview

**Bug:** Wave-65 placed `useMemo(() => adminAlerts, [algConnected])` AFTER the
`if (isLoading || !stats) return <LoadingState />` guard in OverviewSection.
On first render, the hook was skipped (early return). On second render
(when stats arrived), the hook ran. React threw "Rendered more hooks
than during the previous render" → AdminSectionBoundary caught →
"The overview section failed" displayed to the operator.

**Detection method:** Real-fetch via Chrome MCP loaded `/admin/overview`,
got the section-failed boundary instead of the dashboard. `body.innerText`
contained "Rendered more hooks than during the previous render."

**Why typecheck didn't catch it:** TypeScript can't statically analyze
React hook call order. ESLint rule `react-hooks/rules-of-hooks` would
have caught it but isn't configured in the project's lint scripts.

**Fix (wave-73):** Moved `useMemo` and its dependency derivation ABOVE
the early-return guard. After fix: 24 stat-cards render, KPI tiles
visible, alertbar correctly empty (ALG online).

**Production impact window:** wave-65 push (~10:14 AM today) → wave-73
push (~3:55 PM today) ≈ 5.5 hours. Anyone visiting `/admin/overview`
during that window saw the section-failed boundary. Owner-only route,
likely 0 customer impact, but operator-blocking.

## Verification gaps (honest disclosure)

### ⚠️ Wave-43: customer-facing CSS tokens defined but UNUSED

**Claim in commit body:** "tokenize design system into CSS custom properties"

**Reality from grep:** ~45 customer-facing tokens (`--brand-yellow`,
`--ease-magnetic`, `--ring-yellow`, etc.) added to `client/src/index.css`.
Components do NOT reference them via `var(--*)` — they still use Tailwind
utility classes directly (`bg-yellow-500`, hardcoded `cubic-bezier(0.32,...)`).

**Greppable evidence:**
- `var(--data-*)` and `var(--ring-neutral)` etc. are used in 3 admin
  files (wave-50/54/64/65 work) — these ARE wired
- `var(--brand-yellow)` and other wave-43 customer tokens: 0 .tsx files
  reference them
- `cubic-bezier(0.32, 0.72, 0, 1)` appears 31 times as hardcoded value
  across 8 files — should be `var(--ease-magnetic)` per the wave-43 plan

**Implication:** Wave-43 was effectively documentation/scaffolding, not a
functional change. Future updates to brand color or signature easing
require touching 31+ hardcoded sites instead of one token. Honest 50%
completion.

**Fix path:** Either migrate consumers to `var(--*)` (medium effort)
or remove the unused tokens from index.css (cleanup). Filed as
backlog item, not blocking.

## Addendum — sister-bug sweep via scripts/audit-hook-after-return.mjs

After wave-73 caught the OverviewSection hook bug, ran a heuristic
audit across all admin .tsx files looking for the same pattern. Output:

```
$ node scripts/audit-hook-after-return.mjs
✗ 7 suspicious pattern(s):
  client/src/pages/admin/CallTrackingSection.tsx (3 hits)
  client/src/pages/admin/CustomersSection.tsx (1 hit)
  client/src/pages/admin/OutreachHubSection.tsx (1 hit)
  client/src/pages/admin/WorkOrdersSection.tsx (2 hits)
```

Manual inspection of each finding: **all 7 are false positives**.
The script's heuristic doesn't distinguish between an `if (...) return`
at the component's top level vs. an `if (...) return` inside a
callback closure (useState initializer, useMemo callback, useEffect
body). Examples:

```ts
// CustomersSection.tsx:742 — flagged but safe
const [activeTab, setActiveTab] = useState<CustomerTab>(() => {
  if (typeof window === "undefined") return "customers";  // ← inside initializer
  ...
});
useEffect(() => { ... }, [activeTab]);  // ← next hook at top level, OK
```

```ts
// CallTrackingSection.tsx:56 — flagged but safe
const peakHours = useMemo(() => {
  if (!calls || calls.length === 0) return [];  // ← inside useMemo callback
  ...
}, [calls]);
const dayOfWeek = useMemo(() => { ... }, [calls]);  // ← next hook at top level, OK
```

After wave-73's fix, **no real hook-after-early-return bugs remain in
admin**. The audit script is preserved as a future trip-wire — when it
flags zero, the codebase is definitively clean.
